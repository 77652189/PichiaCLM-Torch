# ADR-0009：harmonization 吻合度以"基准设计"为参照报告，不引入吻合度阈值

**状态：** accepted<br>
**日期：** 2026-08-26

## 背景

ADR-0005/0006/0007 之后，%MinMax harmonization 已经能给推荐子集排序：候选在宿主频率下的曲线，与源基因在源物种频率下的曲线，按平均绝对差从小到大排。

但输出里只有顺序，没有"排第一到底算不算接近"。这带来一个和 ADR-0002 当初要解决的完全同构的问题：**排序总能给出一个第一名，哪怕整池候选都离目标曲线很远**。使用者看到"排序依据：源物种 harmonization"和一个有序列表，很容易把排第一理解成"已经完成 harmonization"，而实际可能只是矮子里拔将军。

自然的做法是加一个吻合度阈值。但这里没有可用的数字：文献报告的是 harmonization 方法在特定蛋白上改善了可溶性表达，没有给出"平均绝对差低于多少算合格"这类判据；ADR-0004 已经有过一次教训——把一个文献数字套到不合适的轴上，结果做出一个恒红、毫无判别力的门槛（后由 ADR-0007 移除）。再凭空造一个阈值，是重复同一个错误。

## 决策

**不设吻合度阈值；改为与"基准设计"对比后报告。**

`CandidateSubsetSelection` 新增两个字段（仅在传入 harmonization target 时有值）：

- `harmonization_best_distance`：选中子集里最接近源曲线的那条的平均绝对差；
- `harmonization_reference_distance`：**模型自身的参考 CDS**（`generate_cds_candidates` 里的 `reference`，即未经候选生成的贪心预测）用同一套方法测得的平均绝对差。

接口层据此分三种情况报告：

1. `best < baseline` → 成功：最佳候选比基准更接近源基因的翻译节奏；
2. `best >= baseline` → **明确报错式提示**：这一组里没有候选优于基准，排第一不等于完成了 harmonization，并给出可操作建议（增大候选数、改用温度采样、核对源 CDS 是否对应这段设计）；
3. `best is None` → 无法计算（候选短于一个窗口，或源曲线为空），明确说明这是"算不了"而不是"吻合得好"。

基准之所以是参考 CDS，是因为它就是"不做 harmonization 排序时会拿到的东西"。因此这个报告回答的是一个有意义且可验证的问题——**有没有比不做更好**——而不是拿一个没有依据的常数去判合格。

**这不改变 harmonization 的定位**：它仍然是偏好而非约束（ADR-0005），不淘汰候选、不改变选中了哪几条、不与相似度合成分数（ADR-0002）。新增的只是报告。

## 后果

- 使用者能区分"排序有效且确实改善"与"排序只是给了个顺序"，后者会被显式标红。
- 不引入任何新的、需要日后论证或推翻的魔法数字；判据随序列自我校准。
- 基准本身不是"好"的保证：参考 CDS 可能本来就离源曲线很远，此时即使候选优于它，也不代表吻合得好。报告文案因此只声称相对改善，不声称达标。
- 若将来湿实验或文献给出真正的吻合度判据，可以新开 ADR 在此基础上增加绝对阈值，不与本决策冲突。

## 备选方案

- **凭经验设一个吻合度阈值（如平均绝对差 < 20）**：拒绝。%MinMax 值域为 −100..+100，但"多少算接近"没有任何文献或实验依据；ADR-0004→ADR-0007 已经演示过凭空取值的代价。
- **只报告数值，不做任何判断**：拒绝。原始数字对不熟悉 %MinMax 量纲的人不可读，等于把判断责任推给使用者却不给参照系。
- **把吻合度做成硬门槛，不达标就不返回子集**：拒绝。harmonization 是偏好不是约束（ADR-0005）；把它变成门槛会让一个未经验证的科学假设获得否决权。
- **拿"全部使用最高频密码子"的极端序列当基准**：拒绝。那是一条实际不会被采纳的序列，用它作参照会让几乎任何候选都显得"更好"，报告因此失去判别力。

## 取代关系

无。本 ADR 补充 [ADR-0005](ADR-0005-temperature-sampling-strategy-and-min-max-ranking.md) 中"%MinMax 只排序"的决策，增加了排序结果的可解释性，未取代其中任何决策。本 ADR 如被后续决策取代，应新建 ADR 并在本文件及索引中标明替代关系。
