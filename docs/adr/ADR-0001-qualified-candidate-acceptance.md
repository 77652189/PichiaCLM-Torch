# ADR-0001：最终候选采用相对基准的保守筛选

**状态：** accepted<br>
**日期：** 2026-07-31

## 背景

候选 CDS 生成需要在获得同义多样性的同时，避免以更高的序列风险换取多样性或更高的某一个密码子使用分数。训练数据 CAI 与公开 Kazusa CAI 都是有用但不同参考系下的审查指标；单一 CAI 阈值不能覆盖翻译、局部序列风险或可避免低偏好密码子。

## 决策

保留基准 CDS 作为候选集中的参考。新增的最终候选必须：

1. 翻译回与输入相同的氨基酸序列；
2. 没有关键质量问题；
3. 风险警告数不高于基准；
4. 可避免的最低偏好密码子数不高于基准。

训练数据 CAI、公开 Kazusa CAI 和密码子偏好统计与候选一同输出，供人工比较；它们不作为单独的通过/失败阈值。

## 后果

- 候选数可能少于请求数；设计空间耗尽时必须明确报告，而不是放宽合格条件。
- CAI 更高的候选仍可能不合格；通过的候选也不应被解释为实验成功保证。
- CLI、API 和 Streamlit 必须展示同一核心生成与质量判定结果。

## 备选方案

- 以单一 CAI 阈值决定合格：拒绝，因为它会忽略其他质量风险，并混淆两个参考系。
- 只要求翻译一致和序列唯一：拒绝，因为会允许相对基准增加警告或可避免低偏好密码子。
