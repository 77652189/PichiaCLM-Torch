# ADR-0008：harmonization 要求研发组输入已对齐的成熟肽 CDS，工具不代为对齐

**状态：** accepted<br>
**日期：** 2026-08-26

## 背景

ADR-0006 引入了源物种参考数据（人类密码子频率表 + 天然 CDS），ADR-0005/0007 把 %MinMax harmonization 接成了推荐子集的排序依据。`compare_min_max_profiles` 逐窗口比较两条曲线，因此源曲线的第 *i* 个窗口必须和候选曲线的第 *i* 个窗口描述同一段残基。

但天然 CDS 与表达设计通常**不是**逐位对应的：

- 人类 LTF（hLF）的天然 CDS 含 1–19 位信号肽，而毕赤酵母表达构建一般用自己的分泌信号（α-factor 等）替换掉它；
- SPP1（OPN）有多个转录变体，长度不同；
- 数据库 CDS 记录一般带终止密码子，设计序列一般不带；
- 实际构建还可能带标签、接头、酶切位点。

先前实现只在 `compare_min_max_profiles` 里检查两条曲线窗口数是否相同，长度不等就报错。这个检查太弱也太晚：窗口数相同不代表位点对应（错误的转录变体完全可能长度恰好一样），而且错误发生在算完曲线之后，信息里也没说清该怎么办。

## 决策

**由研发组同事提供已对齐的成熟肽 CDS，工具不做任何对齐、裁剪或补齐。**

在 `generate_cds_candidates` 拿到 `harmonization_target` 后立即校验（`_validated_harmonization_target`），不等到算曲线：

1. 源 CDS 长度必须是 3 的倍数，否则报错；
2. 允许并自动去掉**一个末尾终止密码子**（数据库记录常带，这是格式差异不是对齐差异）；
3. **源 CDS 翻译结果必须与设计的氨基酸序列完全相同**，否则报错。

第 3 条是核心。它比"窗口数相同"强得多：还能抓出转录变体选错、移码、信号肽没去掉但密码子数恰好对上等情况。逻辑依据是——源天然 CDS 与设计 CDS 编码的本来就是同一个蛋白，这是 harmonization 的前提，不成立就没有可比性。

报错信息明确说明该提供什么：同一成熟肽的天然编码序列，去掉信号肽与载体序列，中间不留空缺，并说明工具**不会**代为对齐，因为猜测对齐方式会静默地比较到不相干的位点。

## 后果

- 使用 harmonization 排序前，研发组必须先确定"我们表达的到底是哪一段"，并给出对应的天然 CDS。这个确认工作本来就必须有人做，现在被前置成一个显式输入，而不是藏在一个可能悄悄比错位点的默认行为里。
- 失败在生成流程一开始就发生，错误信息可操作，不是算完一堆曲线之后抛一个"窗口数不一致"。
- `compare_min_max_profiles` 里原有的长度检查保留，作为兜底（该函数是公开的，可能被别的调用方直接使用）。
- 工具不承担对齐职责，也就不会因为对齐算法的选择而引入未经验证的科学判断。

## 备选方案

- **自动裁掉信号肽**（按 UniProt 注释或按前 N 个残基）：拒绝。哪一段是信号肽、表达构建里换成了什么，属于研发组的构建决策；工具按注释猜测，一旦猜错会静默地把整条曲线错位，而结果看起来完全正常。
- **做序列比对（如 Needleman-Wunsch）后按比对结果对齐**：拒绝。引入 gap 之后"第 i 个窗口"的含义就不再明确，%MinMax 是滑窗统计量，插入 gap 会改变窗口内的密码子组成；而且这会把一个明确的输入要求换成一个需要调参、需要单独验证的算法。
- **只检查窗口数是否相同（维持现状）**：拒绝，理由见背景——长度相同不蕴含位点对应。
- **不校验，交给使用者自己保证**：拒绝，与本仓库"不静默继续"的一贯原则冲突。
