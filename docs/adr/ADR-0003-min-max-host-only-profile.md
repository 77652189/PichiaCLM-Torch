# ADR-0003：%MinMax 局部翻译速度谱先算宿主曲线，暂不做源物种对比

**状态：** accepted<br>
**日期：** 2026-08-25

## 背景

`core/analysis.py` 已有 CAI、`find_rare_codon_runs`、局部 GC、homopolymer、重复、motif，但没有 %MinMax（Clarke & Clark 2008）。%MinMax 是滑窗指标（本仓库取 18 个密码子），衡量窗口内实际密码子相对其同义家族的偏好位置，输出沿基因的一条曲线：`+100` 表示这段用了同义家族里最常用的密码子，`-100` 表示用了最不常用的；负值的谷即（相对某个频率参考）可能的翻译暂停位点。

异源蛋白有两条这样的曲线可比：源基因在源物种密码子频率下的曲线（蛋白当初演化时的折叠节奏），以及我们的设计在宿主（毕赤酵母）频率下的曲线。有意义的比较是后者的形状能否重现前者——因为"稀有"是相对宿主判断的，但要保留的暂停模式是功能上守恒的那部分，是相对源物种形成的。

但本仓库目前没有任何"源物种密码子使用频率表"的输入通道：`core/analysis.py` 只有两套宿主参考——训练数据 `load_training_codon_reference()` 和公开 Kazusa `PUBLIC_PICHIA_PASTORIS_FRACTIONS`，两者都是毕赤酵母（宿主）的频率表，不是任何源物种的。

## 决策

`min_max_profile(codons, reference_fractions, window=MIN_MAX_WINDOW)` 的 `reference_fractions` 参数是通用的，不绑定任何物种；`build_fraction_table` 与 `load_training_codon_reference` 已经提供宿主侧的频率表，直接复用。本次调用点只会传入宿主的训练或公开频率表，因此当前算出来的曲线回答的是"这段设计在宿主里翻译速度曲线是什么样"，不是"是否重现了源蛋白的暂停模式"。

函数不假定输入的频率表来自哪个物种，为未来接入源物种频率表留了参数上的扩展点，但源物种对比——包括如何获得源物种频率表、如何对齐源基因与设计序列的位点、如何量化"形状吻合"——不在本次范围内。

## 后果

- 当前 %MinMax 只能在宿主视角下使用：识别宿主翻译速度谷值、供 %MinMax 排序候选（见 ADR-0002 中"约束/偏好不合成一个分数"的原则），不能用于判断源蛋白暂停位点是否被保留。
- 任何呈现层（CLI/API/Streamlit）如果展示 %MinMax 曲线，必须说明这是相对宿主频率的曲线，不得暗示它验证了共翻译折叠暂停位点被保留。
- 源物种对比作为独立的、需要新数据输入（源物种密码子使用表或源基因序列）的后续切片，记入 `docs/HANDOFF.md` 的下一步，需要用户确认数据来源。

## 备选方案

- **现在就编一个"源物种参考表"，或者直接用宿主表冒充源物种表做形状对比**：拒绝，这是在没有真实数据的情况下伪造科学结论，违反"不对未经真实数据验证的科学结论下断言"的既有原则。
- **把源物种对比做成本次必须交付的一部分，先用占位数据实现，等真实数据到位再返工**：拒绝，会导致要么阻塞交付，要么用假数据抢跑一个会被人工当作科学结论看待的曲线；现有代码库完全没有这类输入，属于新的数据依赖，应该单独授权一个切片，而不是塞进本次修改。
- **不做窗口，只用现有的 `find_rare_codon_runs` 连续稀有密码子串近似替代 %MinMax**：拒绝，连续稀有密码子串只能看到局部片段，看不到整条曲线的走势，无法定位非连续但仍显著的暂停位点，也无法做"形状是否吻合"这类比较。

## 取代关系

关于"源物种对比更有意义、只是因为缺数据而推迟"的框定，已被 [ADR-0005](ADR-0005-temperature-sampling-strategy-and-min-max-ranking.md) 取代：用户确认本项目需要的就是宿主（毕赤酵母）视角，训练数据本身也是毕赤酵母的，源物种对比对本项目不适用，不是数据缺口。本 ADR 关于 `min_max_profile` 只算相对某个频率表的宿主曲线这一实现决策未被取代，继续有效。
